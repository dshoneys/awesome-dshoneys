# 安全徽章规范（Badge Spec）

本目录所有插件条目都带一枚**安全徽章**，由社区安全检测助手依据检测报告（模板见 [security-report-template.md](security-report-template.md)）打标。徽章与报告一一对应：**看徽章就能知道这个插件能不能放心用，想看细节点进报告**。

---

## ① 三种徽章与收录规则

| 徽章 | 含义 | 收录规则 | 处置说明 |
| --- | --- | --- | --- |
| `✅ 已通过` | 五项检测（权限滥用 / 恶意代码 / 数据外传 / 密钥窃取 / 依赖风险）全部通过，未发现风险点 | **收录**，正常展示 | 常规收录；后续版本更新需重新检测换发新徽章 |
| `⚠️ 警告` | 存在**低风险**项：不影响安全结论，但有值得注意的行为（如本地明文缓存配置、请求较多第三方接口、依赖偏旧等） | **收录**，并在条目中**公示整改建议** | 收录不等于免责：整改建议会写进检测报告与 README 条目备注，作者修复复检后可升级为 ✅ |
| `❌ 不通过` | 存在**高危**项：确认恶意代码、窃取密钥 / 聊天记录外传、越权滥用等任一情况 | **不收录**，并**公开说明原因** | 已在目录中的发现后立即下架；公示原因以保护群友，确属恶意的不适用「先私聊后公示」流程 |

**未检测 = 没有徽章**：`⏳ 待检测` 不是徽章，只是 PR 阶段的临时状态。未检测的条目一律不合入目录（硬规则「未检测不收录」，见 [CONTRIBUTING.md](../CONTRIBUTING.md) ①）。

---

## ② 判定标准（与检测报告结论的对应关系）

| 徽章 | 检测报告结论 | 判定条件 |
| --- | --- | --- |
| `✅ 已通过` | 通过 | 五项检测全部无风险点 |
| `⚠️ 警告` | 警告 | 存在低风险项，且**不含**任何高危项；报告须附整改建议 |
| `❌ 不通过` | 不通过 | 存在任一高危项（恶意代码 / 密钥窃取 / 敏感数据外传 / 严重越权 / 明显恶意的依赖投毒） |

高危与低风险的边界拿不准时，**从严判定**：宁可给 ⚠️ 也不要含糊给 ✅；拿不准是否 ❌ 时，提交安全检测助手内部复核后再定。

## ③ 用法示例（README 表格）

在 README「分类目录」的插件条目表格中，安全徽章一栏直接使用以下写法（纯文本 emoji，无需任何 badge 服务）：

```markdown
| 名称 | 作者 | 链接 | 简介 | 安全徽章 | 群友实测备注 |
| --- | --- | --- | --- | --- | --- |
| 快捷剪贴板 v0.9.0（虚构示例，待替换） | @example-dev | https://github.com/example-dev/demo-clipboard | 常用提示词侧栏一键粘贴 | ✅ 已通过（示例） | 「分组功能好用」——@群友A，2026-08（示例） |
| 日程速查 v1.2.0（虚构示例，待替换） | @example-dev2 | https://github.com/example-dev2/demo-schedule | 自然语言记日程，自动提醒 | ⚠️ 警告（示例） | 「提醒准确，注意它会本地缓存日程」——@群友B，2026-08（示例） |
```

写作规范：

- **三选一，逐字使用**：`✅ 已通过`、`⚠️ 警告`、`❌ 不通过`，不要写成「通过」「安全」「已认证」「绿标」等变体，方便检索与统计。
- 徽章后用括号附**报告编号**（如 `✅ 已通过（SR-20260821-001）`），报告中级差信息在检测报告落款处；示例条目则标注「（示例）」。
- `⚠️ 警告` 条目必须在「群友实测备注」或条目旁一行写明整改建议要点，与检测报告一致。

## ④ 样式与颜色建议

徽章统一使用 emoji 原生符号，保证在任何 Markdown 渲染环境（GitHub / 群内转发纯文本 / 本地编辑器）下都可读：

| 徽章 | emoji | 建议色（若做 shields.io 徽标） | 语义色 |
| --- | --- | --- | --- |
| `✅ 已通过` | ✅ | `brightgreen`（#4c1） | 绿 = 安全 |
| `⚠️ 警告` | ⚠️ | `yellow`（#dfb317） | 黄 = 注意 |
| `❌ 不通过` | ❌ | `red`（#e05d44） | 红 = 高危 |
| `⏳ 待检测` | ⏳ | `lightgrey`（#9f9f9f） | 灰 = 流转中，非徽章 |

- **默认纯 emoji 文本**：微信群转发、截图、纯文本查看场景多，emoji 在任何地方都不丢信息，这是默认形态。
- **可选增强**：若未来迁移到 GitHub Pages 站点，可叠加 shields.io 徽标（如 `https://img.shields.io/badge/安全-已通过-brightgreen`），但 README 表格内仍保留 emoji 文本作为兜底，两者不互相替代。
- **不要**给徽章加动画、自定义图片或外部图床链接：图床失效会让徽章信息整体丢失，emoji 不会。

## ⑤ 徽章的生命周期

- **换版本 = 重检测**：插件任何实质更新（新权限、新依赖、新网络请求）后，旧徽章不再背书，需重新检测换发。
- **警告可升级**：⚠️ 作者按整改建议修复并复检通过后，升级为 ✅，报告编号更新。
- **通过也可撤销**：✅ 事后被发现高风险行为（如更新通道投毒），立即降级为 ❌ 并下架公示，检测报告标注撤销原因与日期。
- 所有升降级都在 `docs/reports/` 留档，可追溯。
