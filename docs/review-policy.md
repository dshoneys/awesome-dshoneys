# 插件自动评审规则

本仓库对带有 `plugin` 标签的投稿 Issue 自动执行首轮评审。目标是快速响应、固定证据、给出可执行整改要求，而不是用机器人评论代替安全保证。

## 触发方式

- 创建、编辑或重新打开插件投稿 Issue
- 投稿者或维护者在 Issue 回复一行 `/recheck`
- 每 6 小时检查一次所有开放投稿
- 维护者从 Actions 页面手动指定 Issue 复审

机器人只维护一条带隐藏标记的评审评论；证据变化时更新原评论，不重复刷屏。

## 自动检查范围

1. **投稿完整性**：插件名称、公开 GitHub 仓库、简介、作者和 dsh.so 详情页。
2. **外部扫描**：dsh.so 风险级别、critical/warning 数量、扫描时间和版本信息。
3. **固定源码版本**：评审时记录默认分支最新 commit SHA，避免结论与代码错位。
4. **静态能力检查**：动态执行、shell 模式、子进程、网络、凭据、文件写入和下载执行模式。
5. **供应链检查**：安装生命周期脚本、锁文件和未加 scope 的包名。
6. **仓库成熟度**：README、许可证、测试和 CI。
7. **同类线索**：从 dsh.so 页面提取公开相关插件，供最终横向评级使用。

自动评审不会安装或执行投稿插件。需要运行验证时，应另行进入无密钥、无写权限、限制网络与资源的隔离环境。

## 状态标签

| 标签 | 含义 | 下一步 |
| --- | --- | --- |
| `needs-info` | 投稿必填字段或公开仓库缺失 | 投稿者补充后回复 `/recheck` |
| `scan-blocked` | dsh.so 页面没有可核验安全结果 | 等待扫描更新后复审 |
| `changes-requested` | dsh.so 或静态检查发现阻断项 | 作者修复并提供新 commit |
| `review-ready` | 自动硬门槛已通过 | 进入同类比较与最终评级 |
| `duplicate` | 与现有主 Issue 完全重复 | 合并信息后关闭重复项 |

`review-ready` 不等于正式收录。目录只展示最终评级完成并通过收录 PR 的插件。

## 判定门槛

以下任一情况会阻止进入最终评级：

- dsh.so 页面不可访问或没有安全结果
- dsh.so 显示 `high-risk` 或存在 critical 发现
- 内置规则发现动态执行、shell 执行、下载后执行或安装期高风险脚本
- 源码仓库无法读取

warning 会在报告中公示，但不一定单独阻断。最终评级还应核对宣传声明与实际行为、功能可用性、同类竞争力和维护情况。

## 权限与安全边界

工作流仅拥有：

- 仓库内容只读权限
- Issue 标签和评论写权限

它不能推送代码、创建 Release、读取仓库密钥或合并 PR。投稿内容视为不可信输入，工作流不得把 Issue 中的命令直接交给 shell 执行。

## 复审

作者完成整改后，在 Issue 单独回复：

```text
/recheck
```

工作流会重新获取当前默认分支 commit、dsh.so 页面和源码证据，并更新原有报告。为了避免第三方消耗额度，只有投稿者和仓库成员的 `/recheck` 会生效。
