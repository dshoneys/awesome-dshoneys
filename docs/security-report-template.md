# 社区补充复核记录模板（security-report-template）

> [dsh.so](https://www.dsh.so/) 是本目录指定的安全检测服务。本模板仅用于社区补充复核与沟通，不替代、不改写 dsh.so 的公开扫描结果。
> 需要补充记录时，可复制本模板并保存为 `docs/reports/<插件名slug>-<版本>-<复核日期YYYYMMDD>.md`。
> 收录硬条件是可核验的 dsh.so 插件详情页与扫描结果；本地补充记录不是必填，也不能单独作为收录依据。

---

| 项目 | 内容 |
| --- | --- |
| 插件名称 | （如：快捷剪贴板 v0.9.0） |
| 版本 | （如：v0.9.0，与作者发布页一致） |

| 报告编号 | （格式：`SEC-<YYYYMMDD>-<序号>`，如 SEC-20260821-001，编号当日递增、不重复） |

> dsh.so 两项链接、插件版本与复核者缺一不可；版本号必须与 dsh.so 页面及作者发布页一致。

## 二、检测项清单

五类风险逐项检测，每一项都要给出「检测说明」（做了什么、怎么判断）与「结果」（未发现问题 / 发现问题+具体描述），不允许留空或写「略」。

| # | 检测项 | 检测说明 | 结果 |
| --- | --- | --- | --- |
| 1 | 权限滥用 | 检查插件申请的每一项权限（文件读写、剪贴板、网络、开机自启、通知等）是否与其声明的功能匹配；记录权限清单并逐项核对必要性 | （未发现问题 / 发现问题：具体哪项权限超出功能所需，举例说明） |
| 2 | 恶意代码 | 通读源码，检索可疑模式：混淆/加壳代码、动态下载执行（eval、远程加载脚本）、计划任务/持久化写入、进程注入、删库或破坏性操作 | （未发现问题 / 发现问题：位置+行为描述） |
| 3 | 数据外传 | 追踪所有网络出口：请求的目标域名/IP、上报的数据字段、频率与时机；判断是否将用户对话内容、剪贴板、本地文件等发送到非功能必需的服务器 | （未发现问题 / 发现问题：外传目标+数据内容+触发条件） |
| 4 | 密钥窃取 | 检查是否读取、存储、上传 API Key / token / cookie / 钥匙串 / `.env` 等凭据类文件；密钥若确需本地保存，核对保存位置是否明文、是否出网 | （未发现问题 / 发现问题：涉及哪类凭据、去向） |
| 5 | 依赖风险 | 检查第三方依赖清单：是否有已知高危 CVE、是否引用无人维护/突然重发布的可疑包（typosquatting、依赖混淆）、是否锁定了版本 | （未发现问题 / 发现问题：依赖名+风险类型+建议版本） |

> 填写提示：
> - 「检测说明」写**实际做过的动作**（如「grep 全部网络调用，共 3 处，目标均为插件自述的统计域名」），不要写套话。
> - 发现问题时必须写清**代码位置（文件/行号或函数名）+ 行为 + 影响**，便于作者定位修复与复检。

## 三、结论分级

按检测项结果给出三级结论之一，并在对应级别内补全附加内容：

### ✅ 社区复核未发现补充问题

**判定标准**：五项检测全部未发现问题。

- 是否收录及徽章状态仍以 dsh.so 公开结果和 [badge-spec.md](badge-spec.md) 为准。
- 若有值得提醒的小观察，写入附注，并明确这是社区补充信息。

### ⚠️ 警告

**判定标准**：存在低风险项——问题真实存在，但不涉及恶意意图、不危害用户数据与凭据，且通常可配置规避或短期可修复（如：权限略超所需但有关闭开关；依赖存在低危 CVE；统计上报过勤但数据不含敏感字段）。

**必须附整改建议**，逐条写明：

| 风险项 | 建议 | 建议期限 |
| --- | --- | --- |
| （对应检测项编号与问题） | （具体怎么改：砍掉某权限 / 升级某依赖 / 增加开关默认关闭） | （如：下个版本，2 周内） |

- 将补充风险提交维护者核验；公开目录不得用本记录覆盖 dsh.so 结论。

### ❌ 不通过

**判定标准**：存在高危项——恶意代码、密钥窃取、未声明的敏感数据外传、破坏性行为，或多条警告长期不改并叠加。

**必须附不通过原因**，逐条写明：

| 风险项 | 原因（行为+影响+代码位置） | 是否已私聊作者 |
| --- | --- | --- |
| （对应检测项编号与问题） | （具体描述，证据写清，供复现章节引用） | （是/否，日期） |

- 暂停收录或下架，并将证据提交维护者及 dsh.so 复核。
- 除确属恶意的情况外，结论公示前先走「私聊作者→修复→复检」流程（见 [CONTRIBUTING.md](../CONTRIBUTING.md) ②）。

**本次社区复核结论**：（未发现补充问题 / 需要注意 / 建议暂停收录）

## 四、复现方式

以**步骤化记录**写出检测中关键发现的复现过程，任何人照做应能得到同样结果；全部通过的报告则复现「验证通过」的检查动作。

```text
1. 环境准备：（系统/版本、插件运行环境、抓包或分析工具及版本）
2. 获取样本：（下载链接、commit/版本号、文件哈希 md5/sha256）
3. 操作步骤：（第 1 步做了什么 → 观察到什么；第 2 步 ……）
4. 预期结果：（复现时应看到的现象，如「Wireshark 中可见 POST xxx.com，body 含剪贴板内容」）
```

示例（虚构演示，待替换为真实记录）：

1. 环境准备：macOS 15 / Python 3.12 / mitmproxy 11（示例环境）。
2. 获取样本：`https://github.com/example-dev/demo-clipboard`，tag v0.9.0，sha256 `abc123…`（虚构示例）。
3. 操作步骤：启动 mitmproxy → 打开插件 → 复制一段文本 → 观察 10 秒内的出网请求。
4. 预期结果：仅见一次 POST 至 `stats.example.com`，body 仅含事件名，无剪贴板内容（示例结果）。
